# 01_design_system — 디자인 규칙 (전원 공용)

이 문서는 **디자인의 규칙·이름·근거·참고 URL**만 둔다. 색·글꼴·크기·간격 같은 **실제 값은 적지 않는다.**

- 값의 정본: **`app/mockup/common.css`**(대표 화면 ①에서 생성·확정 — `app/roadmap.md` §2 2~3단계). 생기기 전까지 `app/ui.py`·`.streamlit/config.toml`은 실행 중인 앱의 임시 값일 뿐 디자인 기준이 아니다.
- 화면이 답하는 질문·데이터·집계 정의는 `00_common.md`와 페이지별 `<번호>_<키>.md`에 있다. **데이터 사실은 md 우선, 디자인 값은 `common.css` 우선**(`00_common.md` §7·§11).
- 회의 결정(제목·부제·「반도체」 어휘·과천 라벨 등)은 `00_common.md` §8 한 곳에만 있다.

## 0. 판단 기준 — 믿고 쓸 수 있는가

디자인 선택이 갈리면 「이 화면의 숫자를 믿고 인용할 수 있는가」로 정한다(2026-09-23). 장식보다 데이터 가독성이 먼저다.

1. **숫자 옆에 단위·기간** — KPI·축·표 머리에 단위(억 달러·건·개)와 기간(연도·「기간 합계」)을 붙인다. 긴 한글 품목명은 줄바꿈해 읽히게 하고 자르지 않는다.
2. **같은 조건을 보고 있음을 표시** — 필터 바로 아래 「현재 조건 줄」(품목·기간·단위) 한 줄을 두고, 그 아래 KPI·차트·표가 모두 그 조건임을 보인다.
3. **출처는 가까이, 산식은 펼쳐서** — 차트·표 바로 아래 출처 한 줄, 산식·설명은 펼침(§5 `expander`·`popover`). 내려받은 CSV에도 조건·단위·자료 기간을 남긴다(`ui.csv_header`).
4. **증감을 좋음·나쁨 색으로 읽히게 하지 않는다** — 수입 증가·집중도 상승은 좋고 나쁨이 아니다. 증감은 부호·화살표로만(§2).
5. **쉽게 읽히고, 필요하면 깊게** — 첫 화면은 간결하게, 근거·상세 표는 펼침·조회 화면에서 끝까지 확인할 수 있게(연구·분석 그룹).

유지하는 구분: 수입 파랑·수출 주황, 부분연도 표시, **실제 0 / 미적재 / 조회 실패**의 구분.

## 2. 색 — 두 층

토큰 이름은 `common.css`의 CSS 변수·Figma 색 스타일 이름과 같게 쓴다. 값은 `common.css`에만 있다.

**① 대표색 층** — C의 대표색·테마에서 파생. 대표색을 바꾸면 이 층만 바뀐다.

| 토큰 | 역할 |
|---|---|
| `brand` · `brand-weak` · `on-brand` | 대표색(선택된 메뉴·버튼·구역 태그) · 옅은 대표색(선택 배경) · 대표색 위 글자 |
| `bg` · `topbar-bg` · `panel` · `panel2` | 페이지 · 상단바 · 카드 · 카드2 배경 (테마의 중립색 단계) |
| `line` · `zone-line` | 카드 테두리·차트 격자 · 구역 테두리 |
| `text` · `muted` · `caption` | 본문 · 보조 글자(라벨·축) · 출처 캡션 |

**② 고정 층** — 데이터 의미에 붙은 색. 대표색·테마가 바뀌어도 **색상 계열은 유지**한다(테마에 맞춰 명도만 조정).

| 토큰 | 역할 | 계열 |
|---|---|---|
| `imp` · `imp-dim` | 수입 시리즈 · 수입 부분연도(점선) | 파랑 |
| `exp` · `exp-dim` | 수출 시리즈 · 수출 부분연도(점선) | 주황 |
| `delta` | KPI 전년비·증감 — **부호(+/−)·화살표만, 색은 중립**(`muted` 계열). 수입 증가·집중도 상승을 좋음·나쁨으로 칠하지 않는다 | 중립 |
| `ok` · `warn` | 상태 표시 — 정상 / 조회 실패·경고. 데이터 값의 증감에는 쓰지 않는다 | 초록 · 빨강 |
| `badge-text` · `badge-line` | 「잠정」·「인용」·「정부안」 배지 | 노랑 |
| 국가 색 | 국가별 고정색 + 추가 국가 색 + 기타 1색. 같은 국가는 모든 차트에서 같은 색 | — |

**충돌 규칙**

- 초록·빨강은 **상태**(정상 / 실패·경고)에만 쓰고, 데이터 증감에는 쓰지 않는다. 대표색으로 쓰지 않는다. PROJECT.md 원칙 4의 「초록 = 증가, 빨강 = 감소」를 글자대로 따르지 않는 이유: 수입·수출·집중도의 증감은 좋고 나쁨이 아니어서, 색이 판단을 대신하면 「의미 있는 색」이라는 원칙 취지에 어긋난다.
- 대표색이 수입 파랑·수출 주황과 헷갈릴 만큼 가까우면 **대표색 쪽을** 조정한다(고정 층은 바꾸지 않는다).
- 부분연도 = 같은 색의 저채도 + 점선.

## 4. 프레임 · 그리드 원칙

- **데스크톱 한 장**만 설계한다. 모바일은 만들지 않는다(Streamlit이 자동 축소, `00_common.md` §9).
- 폭·여백은 `.block-container` 값 하나를 따른다(`common.css`). 격자는 `st.columns`에 대응하는 12열.
- 배치는 **위→아래 블록 + `st.columns` 격자**뿐이다. **사이드바 없음** — 필터는 본문 필터 줄에 둔다. PROJECT.md 원칙 2(좌측 사이드바 필터)와 다른 이유: 필터를 KPI·차트 바로 위에 두어야 「같은 조건」(§0-2)이 한눈에 보이고, 페이지마다 조건이 달라 사이드바에 모으면 어느 화면의 조건인지 흐려진다(09-20 결정).

## 5. 컴포넌트 — Streamlit 어휘 8개

아래 8개 밖의 요소는 목업·Figma에 넣지 않는다(Streamlit에서 구현할 수 없다).

| 컴포넌트 | 구성 | 대응 코드 |
|---|---|---|
| **상단바** | 브랜드 · 메뉴 · 기준일. 선택된 메뉴 = `brand-weak` 배경 + `brand` 밑줄 | `ui.top_bar()` |
| **구역 틀** | `zone-line` 테두리 + 왼쪽 위 `brand` 태그 | `ui.zone(key, tag)` |
| **카드** | `panel` 배경 + `line` 테두리 | `.card` |
| **KPI 카드** | 카드 + 라벨 / 값 + 단위 / 설명. 배지는 라벨 오른쪽 | `ui.kpi()` |
| **KPI 줄** | 가로 5등분(또는 4등분), 높이 동일 | `.kpis` / `.kpis.k4` |
| **필터 줄** | 드롭다운 · 슬라이더 · pills · 세그먼트 버튼 | `st.selectbox` 등 |
| **현재 조건 줄** | 필터 바로 아래 한 줄: 품목 · 기간 · 단위(· 부분연도 여부). 아래 KPI·차트·표가 모두 이 조건 | `st.caption` 또는 `.cond` |
| **펼침** | 출처 아래 「산식·설명」, 상세 표. 첫 화면은 닫힌 상태 | `st.expander` · `st.popover` |

**차트**는 자리표시자 + 제목 + 범례까지만 정한다. 내부 디자인은 Plotly가 그리므로(`ui.style_fig`) 목업에서 정해도 옮겨지지 않는다. 크기 · 위치 · 제목 문구 · 범례 색만 각 md §4에 적는다.

**상태 5종**(로딩 중 · 데이터 없음 · 조회 실패 · 미적재 · 부분연도)은 목업에 모두 넣는다. 문구는 각 md §6.

### 넣지 않는 것

- 자유 배치(절대 좌표) 레이아웃
- 커스텀 그림자 · 그라데이션 · 유리 효과
- 마우스 올림(hover) 상태, 애니메이션, 전환 효과
- 3D 차트 · 게이지 · 왜곡 인포그래픽 (`PROJECT.md` UI/UX 원칙 3)
- 무기체계 사진 등 이미지 (저작권·출처 — `benchmark-ui-changes-2026-09-20.md` §1 #4)

**연결** — `.mcp.json`의 `figma`(Framelink `figma-developer-mcp`, 무료 요금제 가능, **Figma → 읽기**). 토큰은 각자 환경변수로만 둔다.

## 7. 생성 프롬프트 — "css 재편해줘" · "specs 처리해줘"

Claude는 이 절 순서대로만 `common.css`를 만든다. 사람이 입력을 바꾸는 곳은 §1 A·B·C뿐이다.

1. **입력 확인** — §1 A1(큰 틀)·C(대표색·테마)가 비어 있으면 멈추고 무엇이 비었는지 알린다. B가 3개 미만이면 경고만 하고 진행한다.
2. **보기** — A·B의 URL을 Claude in Chrome으로 열어 표에 적힌 요소만 확인한다. 캡처는 저장하지 않는다.
3. **색 생성** — §2 ① 대표색 층을 C에서 파생하고, ② 고정 층은 계열을 유지한 채 테마 명도만 맞춘다. §2 충돌 규칙을 적용한다.
4. **대비 검사** — `dataviz` 스킬의 검증기로 글자·배경, 시리즈 색끼리(수입 vs 수출, 본 vs 부분연도) 대비를 확인한다. 실패하면 ① 층을 조정한다.
5. **글꼴·간격** — §3 역할 이름, §4 원칙으로 변수를 만든다. 간격은 한 단위의 배수, 모서리는 한 값, 숫자는 tabular 정렬.
6. **배치** — A의 블록 순서를 §5 요소 8종으로만 옮긴다. 「넣지 않는 것」은 넣지 않는다.
7. **출력** — `app/mockup/common.css` 한 파일만 쓴다(CSS 변수 + §5 컴포넌트 클래스). **md에는 값을 쓰지 않는다.** 대표 화면 ① 목업(`app/mockup/20_trade.html`)을 다시 만들어 Artifact로 게시하고, 바뀐 입력·대비 결과를 한 줄로 보고한다.
