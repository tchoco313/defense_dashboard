## D-01. `ref_fsg` FSG60 전자 플래그 — 수정 완료

**원인**
- 60을 1로 고친 적이 있다(09-19 `alter_2026-09-19_p3_clean.sql` §5). 09-21 M4 확정 때도 1로 실측됐다.
- 그런데 시드 파일 `db/seed_ref.sql`의 60 행은 09-16 값 **0**으로 남아 있었다. `scripts/load_db.py --ref`는 이 시드를 실행할 때마다 `ON DUPLICATE KEY UPDATE`로 **덮어쓴다**.
- 09-23 반도체 참조표를 적재하려고 `--ref`를 돌렸을 때 60이 0으로 되돌아갔다. 하위 FSC 24개는 시드 대상이 아닌 `ref_fsc`에 있어 1로 남았고, 그래서 상위와 하위가 모순됐다.

**조치(A안)**
- `seed_ref.sql` 60 행을 1로 고쳐 재발을 막았다.
- DB 값은 팀원 한 분이 먼저 1로 고쳐 두었다. 이 alter는 그 상태를 확인만 했다(UPDATE 0행). 시드 파일은 고쳐지지 않은 채였으므로, 이번에 시드를 고친 것이 재발 방지의 핵심이다.
- 검증: FSG↔하위 FSC 플래그가 어긋나는 그룹은 **0개**다.

**영향**: 이 플래그를 읽는 `v_b2_fsg_summary`는 B2에 60군 행이 없어 값이 같다. 앱은 `ref_fsg`에서 이름만 읽는다. `clean_kdsis_nsn`(317행)과 국외조달 API(11행)는 각자 플래그를 따로 두고 있고, 이미 1이다.

**팀 결정**: A. 09-21 M4 확정 기준(58·59·60)을 되돌린 것이라 새로 합의할 내용은 없다.

## D-02. `ref_hs6_name` HS6 명칭 3건 누락 — 수정 안 함

**원인**: `ref_hs6_name`은 관세청 「HS부호 단위별 품목명」(15130660)의 **06시트(6단위)**로 만든다. 이 시트는 **10자리로 더 나뉘는 HS6만** 싣는다. 10자리 자식이 1개뿐인 HS6는 06시트에 행이 없고, 이름은 10시트에만 있다.

| 실측 | 값 |
|---|---:|
| HS 마스터의 HS6 | 5,613 |
| 06시트에 있는 HS6(`ref_hs6_name`) | 2,254 |
| 06시트에 없는 HS6 | 3,359 |
| └ 그중 HS10 자식이 1개 | **3,345** |
| └ 끝이 `00`인 호(4단위가 6단위에서 안 나뉨) | 14 |

852692·854142·901420은 모두 HS10 자식이 1개다. 누락이 아니라 원본이 원래 이런 구조다.

**이미 처리됨(09-19)**
- 보정 규칙은 ① 06시트 → ② 없으면 앞 6자리가 같은 10자리 행이 **정확히 1개**일 때 그 이름 → ③ 그래도 없으면 NULL이다.
- `ref_hs_rule_flag.hs6_name_ko`에 세 코드 모두 `10시트단일`로 이름이 들어 있다.
- 근거 문서는 `docs/reference/hs-whitelist-definition.md` §8-3이다.

**협의안 선택지에 대한 의견**
- **A(원본에서 다시 확인)**: 공식 원본 06시트에는 처음부터 행이 없다. 공식 명칭은 10자리 행 이름 하나뿐이라, 확인해도 C와 같은 결과가 나온다.
- **C의 우려**(HS6 이름과 HS10 이름이 다를 수 있음)는 자식이 여럿일 때 해당한다. 현재 규칙은 자식이 **정확히 1개**일 때만 쓴다.
- NULL이 되는 곳은 ①만 읽는 `v_hs6_candidate_rule` 하나다. ②를 넣어도 R1~R4 판정은 같다(09-19 실측).
- 화면 영향은 없다. `dashboard/`에는 `ref_hs6_name`·`hs6_name_ko`·`v_hs6_candidate_rule`을 읽는 코드가 없다.
- 「무선원격조**종**기기」(화이트리스트)와 「무선원격조**절**기기」(공식)가 다른 것은, 화이트리스트 이름이 팀이 붙인 표시명이기 때문이다.

**팀 결정 제안**: C(자식 1개일 때만)는 이미 적용되어 있으므로 추가 작업이 없다.

### 판단번호 grain — 수정 안 함, A안 권장

**B안(원본 행을 모두 더하기)을 권하지 않는 이유**
- 5쌍 중 일부는 **같은 계획의 상태가 갱신된 것**으로 보인다(추론). PAMH4008001은 예산 13.3억이 같고 10월 「판단완료」에서 12월 「계약」으로 바뀌었다. PABB4006001은 8월에서 12월로 가며 예산이 수정됐다. 모두 더하면 같은 사업을 두 번 세게 된다.
- 반대로 BBBB0001001은 품명이 달라 별개 계획일 수 있다. 어느 쪽인지 원본만으로는 단정할 수 없다.

**크기**
- 빠진 예산은 23.6억 원으로, 전체 18.26조의 **0.013%**다.
- 연도별로 가장 큰 곳은 2024년 19.1억(그해의 0.11%)이다. 화면 단위(억·조)로 반올림하면 보이지 않는다.

**권장**
- A안: 판단번호 단위를 유지하고 "판단번호 단위"라고 라벨을 단다.
- 원본 전체 합이 필요하면 원본 파일에서 직접 계산한다(18.26조).

**참고(수정 안 함, 팀 판단)**
- 대표 행은 「먼저 나온 행(row_id 최소)」이다. 그래서 PAMH4008001·PABB4006001의 계약 확정 건수가 2건 적게 잡힌다.
- 대표를 「최신 행」으로 바꾸면 연도·품명·예산도 함께 바뀐다. 바꿀지는 팀이 판단할 일이다.

## D-04. 국외조달 API FSC/FSG 모집단 — 수정 안 함

**현황**
- 뷰 `v_overseas_plan_api_fsc`(13,236)는 09-19에 「NSN이 있는 행 전체」로 바뀌었다. 영숫자 NSN 포함은 09-21 M4 확정 사항이다. FSC 카탈로그 일치는 조건에 없어서 카탈로그에 없는 FSC 3행(4902·5585·6652)이 들어간다. 모두 비전자이고, 품명으로 보아 원본 FSC 오기로 보인다(추론).
- **화면은 이 뷰를 읽지 않는다.** 조달·국산화 근거 화면(`dashboard/pages/3_조달_국산화_근거.py`)은 clean 표를 직접 읽는다.
  - 전자 건수는 2,267로, 협의안의 모든 후보에서 같다.
  - 군별 전자 비중의 분모는 **FSG 판별 가능 − FSC 9999 = 13,017**이다(09-23 EDA 계획 B1·B2, 09-24 반영).
- 협의안 후보표에는 13,017이 없다. 13,017은 D(13,014)에 카탈로그 밖 FSC 3행을 더한 값이다.

**판단**
- **A·B(숫자13만)**: 09-21 M4(영숫자 NSN 포함)와 충돌하므로 제외한다. 카탈로그에 100% 맞는 영숫자 3,266행(전자 440)이 빠진다.
- **C(9999 포함)는 비권장**
  - 9999 행 219개 중 218개는 한국(NCB 37) 번호(`999937…`)이고, 품명이 ENGINE·OIL PUMP·LENS·HUB·DESK CONTROLLER CKT처럼 여러 군급에 걸친다.
  - 공식 이름은 「기타 품목」이지만 실제로는 **군급 미분류 자리**로 쓰인다(추론). 분모에 넣으면 전자 비중이 인위적으로 낮아진다.
  - 따라서 화면처럼 빼는 것이 맞고, 방향은 협의안 D와 같다.
- **13,017과 D(13,014)의 차이**: 비전자 3행이라 전체 전자 비중 차이는 0.01%p 미만이다(17.416% 대 17.420%). 바꾸지 않아도 된다.

**팀 결정 제안**: 현재 화면 기준 13,017을 유지한다(D + 카탈로그 밖 3행). DB는 수정하지 않는다.
- 선택 사항: 화면 주석의 「임시 FSC 9999」를 「FSC 9999(기타 품목, 사실상 미분류)」로 바꾸면 공식 명칭과 맞는다. 제안만 하고 고치지는 않았다.

## 재발 방지 (09-28 적용)

네 건의 공통 원인은 **한 곳을 고칠 때 연결된 다른 곳을 같이 고치지 않은 것**이다(D-01 DB ↔ 시드, D-03 새 규칙 ↔ 이미 끝난 정제, D-04 화면 ↔ 뷰). 그래서 규칙을 추가하고, 기억에 기대지 않도록 자동 점검도 두었다.

| 장치 | 내용 |
|---|---|
| 규칙 `data-cleaning-rules.md` §1 #14~#16 | #14 `ref_` 값은 시드·CSV와 같은 커밋에서 고친다 · #15 공용 규칙은 이미 적재한 데이터셋에도 소급하고, 새 clean_ 표는 점검 설정에 등록한다 · #16 같은 질문의 기준은 한 곳에 둔다(화면 분모를 바꾸면 뷰도 맞추거나 「화면 미사용」 주석) |
| `load_db.py --ref` 방어 | 시드와 DB가 다르면 시드를 **건너뛰고 차이를 출력**한다. 덮어쓰기는 `--seed-overwrite`를 붙일 때만 한다. D-01 상황을 재현해 멈추는 것까지 확인했다 |
| `scripts/check_integrity.py` | ① 시드·CSV ↔ DB 값 ② 원본 = clean + 제외 검산(미등록 clean_ 표도 FAIL) ③ 전자 판정 58·59·60 일치. 09-28 실측 **FAIL 0 · PASS 34 · SKIP 5** |
| 단위 테스트 `tests/test_check_integrity.py` | 시드 해석·값 비교, 시드의 전자 군급이 58·59·60인지 확인(DB 없이 실행) |
