## 4. 배포 중 오류와 교훈 — `ui.py`에 새 이름을 추가하면 공개 앱이 깨진다

- **증상**: `f316247` push 직후 공개 앱의 홈과 ①이 `ImportError`(`from ui import … LABEL_POS …`). ③·⑤는 정상.
- **원인**: Streamlit Community Cloud는 재배포 때 이미 메모리에 올린 `ui` 모듈을 다시 읽지 않는다. 지도 라벨 위치표 `LABEL_POS`를 홈에서 `ui.py`로 옮겨 홈·①이 같이 쓰게 했는데, 서버의 예전 `ui`에는 그 이름이 없었다. `ui`의 **기존 이름만** 쓰는 ③·⑤는 영향이 없었다. 가짜 DB 로컬 검증은 매번 새 프로세스라 이 문제가 드러나지 않았다.
- **수정**(`aca0d3b`): `LABEL_POS`를 `ui.py`에서 빼고 홈은 원래 자리로, ①은 같은 값을 자체 보유(파일 주석에 이유 기재). push 1~2분 뒤 복구 확인.
- **규칙**: `app/ui.py`에 **새 이름을 추가하고 페이지에서 import** 하는 변경을 push 할 때는, push 뒤 앱 오른쪽 아래 Manage app → Reboot 를 하거나 새 이름을 페이지 쪽에 둔다.
- **추론(확인 안 함)**: 같은 방식으로 import 하는 `app/db.py`도 마찬가지일 것이고, 공용 모듈의 기존 함수 내용만 바꾼 경우에도 재부팅 전까지 예전 동작이 남을 수 있다. 공용 모듈을 고쳤으면 재부팅이 안전하다.
