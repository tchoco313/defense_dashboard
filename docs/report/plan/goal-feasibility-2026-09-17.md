## Q1. 수입 축·국내 축이 무엇을 설명하는가

반은 맞고 절반은 정정이 필요하다. 용어와 역할을 나눠 보면:

### 수입 축 — R1~R4는 "의존도"가 아니라 "왜 이 품목군을 봤는가"

| 무엇 | 설명하는 것 | 설명 못 하는 것 |
|---|---|---|
| R1~R4 선정 규칙표(`ref_hs_rule_flag`, 84·85·88·90류 HS6 1,003개 전수) | "24개 HS6를 왜 골랐는가" = 국방 관련성 근거 등급. R1 군용전용 HSK 세분류 / R2 항공·항행·레이더 세분류 / R3 이중용도 전략물자 / R4 B2 FSC 대응. 진입 = R1 or R2 or (R3∧R4) | 수입이 어디에 몰려 있는지는 이 표에 없음 |
| 관세청 HHI·상위국 점유율(`v_hhi_hs6_year`) | "그 품목군의 국가 전체 수입이 어느 나라에 몰려 있는가" = 수입 집중도 | 군수 수요 비중, 원산지, 국내 생산 대비 의존율 |

그래서 발표 문장은 **"R1~R4로 고른 품목군의 수입 집중도"**이지 "수입 의존도"가 아니다. 문서 전체가 "의존도"·"의존율" 표현을 금지하고 있고, 어제 검토 문서 §1-2 R-2에서 그 표현이 회의 기록에 남아 있는 걸 지적한 이유다. 그리고 R4는 아직 후보 대응표로 만든 값이라 대응표 확정 전까지 R4 근거는 잠정이다(§2-3).

### 국내 축 — "국산화 이력"과 "국외 조달 계획 건수"까지, "국내 수요"는 아님

| 데이터 | 키 | 설명할 수 있는 것 | 한계 |
|---|---|---|---|
| B2 국산화개발품목(33,965행 → 부품 12,788) | FSC4 | "이 품목군(FSC)에 국산화 완료 부품 N건이 있다" → FSC4→HS6 대응표로 24개 품목군 옆에 붙임 | 지상 28개 사업 한정, 시점 미상, 모수 없음(국산화율 불가). 대응표 17행 전부 후보라 현재 `v_review_list`에서 전부 NULL |
| 국외 조달계획 API(13,615행) | NSN→FSC4 | "국외에서 조달 계획된 품목이 어느 FSC에 몇 건인가" (건수만) | 금액 통화 미검증, 계획이지 실적 아님, HS6 조인 뷰 없음 |
| KDSIS NSN(고유 135,864) | NSN | NSN → FSC·품명·CAGE 수·참조번호 조회. "표준화 등록된 품목이고 제조사 코드가 몇 개다" | 카탈로그 스냅샷. 조달·수요·재고 아님. 연결률 API 4.5%·B2 1.3%. 문서상 "지표 미사용, 보조 조회" |
| FSC/FSG 참조표 | FSC4/FSG2 | 위 세 데이터의 공통 품목군 라벨 | 라벨일 뿐 |
| 계약정보 43,112행(1만 건 요건) | 없음 | — | FSC·NSN이 없어 품목군에 못 붙임. 계약명 키워드 5분류뿐, 정제 0행 |

정리하면 국내 축으로 "어느 정도 설명"되는 건 **② 국산화 근거(B2 완료 이력 + B1 공고)**와 **FSC별 국외 조달 계획 건수**까지다. "국내 조달 수요·실적"은 계약정보에 품목 식별자가 없어서 설명이 안 되고, KDSIS는 그 빈자리를 채우는 게 아니라 NSN이 나왔을 때 품명·제조사를 찾아보는 사전 역할이다.

### 지금 상태로 발표하면

- **수입 축**: R1~R4 표 + HHI는 DB에 값이 있어 설명 가능. 단 HHI 상위 5개 중 3개가 팀판단 품목이라 정렬 층화가 필요(§5-2).
- **국내 축**: 설계와 뷰는 있지만 대응표 확정 alter 미적용 + KRIT·계약정보 정제 0행이라 화면에 나올 값이 없음. §6-B의 B-1(대응표 확정)·B-2(정제 적재)가 선행돼야 "국산화 근거" 열이 처음으로 채워진다.

B-1은 팀 결정 후 Claude가 적용할 수 있고, B-2는 팀원 노트북 영역이다.

### 2. 기획서 목적 — "스크리닝 도구", 결론이 아님

기획서 목적은 「무엇을 먼저 국산화 검토 대상에 올릴 것인가」에 답하는 스크리닝 도구이고, 산출물은 "국산화 필요" 결론이 아니라 2단계 정성 검토 전 상태의 **추가 검토 목록**이다. 즉 목표를 이미 "데이터로 증명 가능한 선"까지 낮춰 놓았다. 어제 검토 문서에서 "국산화 필요성·사업성 근거 없음"이라고 한 것은 이 목표를 흔들지 않는다 — 애초에 그걸 하겠다고 하지 않았기 때문이다.

|---|---|---|---|

| ③ 검토 목록 + 검토표 6항목 | ①②가 되면 자동 | 미구현 | ①②에 종속 |

### 충족을 위한 조건 3개

1. **대응표 확정** (팀 결정 → Claude가 `alter_2026-09-17_category_map.sql` 적용). 이게 없으면 ②의 B2 열이 영원히 NULL이고, 국내 축이 발표에서 빈 표로 나온다. 팀 회의 한 번이면 끝나는 일이라 가장 먼저 풀어야 한다.
2. **계약정보·KRIT 정제 적재** (팀원 노트북 영역). 계약정보는 1만 건 요건의 근거이면서 5분류 속성이 EDA 보고서의 본체다. KRIT는 2행뿐이라 23-4차~26-2차 7파일을 마저 추출해야 "B1 대상" 열이 의미를 가진다.
3. **Streamlit 화면 ⓪①③ 구현** — DB 값이 있는 ⓪①부터 만들면 ②가 늦어져도 발표는 된다. ②는 조건 1·2가 끝나는 대로 붙이면 된다.

세 가지가 되면 "정량 관문으로 거른 품목군 옆에 국산화 근거를 놓는 스크리닝 도구"라는 목표는 충족된다. 반대로 조건 1·2가 안 되면 국내 축이 빠진 "관세청 수입 집중도 대시보드"가 되고, 그건 기획서 목적의 절반이다.

발표 문안에는 "하지 않는 것"(§6-C: 군수 수요 비중·대체품·사업성·국산화율)을 명시해 두는 것이 안전하다 — 목표를 달성했는지는 결국 "스스로 정한 선을 지켰는가"로 평가되기 때문이다.

## Q3. R1(HSK-군용)과 R2(HSK-항공/항행)의 차이

둘 다 **관세청 HS 10단위 세분류 이름에 적힌 "용도"**를 근거로 삼는 규칙이고, 차이는 용도의 종류와 그에 따른 **근거 강도(priority)**다. (`docs/reference/hs-whitelist-definition.md` §8-2, `db/schema.sql` 205~206행)

| | R1 HSK-군용 | R2 HSK-항공/항행 |
|---|---|---|
| 조건 | HS6 아래에 군용 전용 HSK10 세분류가 1개 이상 — 이름에 `제9301호ㆍ제9306호의 물품에 전용`(군용 무기·탄약에 쓰는 것)이 들어감 | HS6 아래에 항공기용·항공용·우주항행 / 무인기 / 레이더 / 항행 HSK10 세분류가 있거나, HS6 공식 명칭 자체에 그 용도어가 있음 |
| 용도의 성격 | 군 전용 — 관세청이 "무기·탄약용"이라고 따로 코드를 판 것 | 군·민 공용 — 민항기·선박 레이더·상용 항행기기도 같은 코드 |
| priority | 1 | 2 |
| 84·85·88·90류 1,003개 중 해당 | 3개(854231·854233·854239 집적회로만) | 52개 |
| 화이트리스트 24개 중 | 3개 | 7개 유지 + 신규 후보(852610 레이더 · 852691 무선항행 · 852990 부분품 · 901420 항공·우주 항행 · 901480 항행기기 · 841191 터보제트 · 880730 무인기 부분품 · 852910 안테나 · 901410 컴퍼스 · 901490 항행 부분품) |
| 판정 방법 | HSK10 이름 문자열 매칭(`mil_cnt > 0`) | HSK10 이름 또는 HS6 명칭 정규식 `레이더\|항행\|항공기용\|항공용\|우주항행\|무인기` |
