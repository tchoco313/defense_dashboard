# 예산·연구개발 자료의 DB 연결 방안 (2026-09-17)

> 검토 요청: 훈희 님. 드라이브 `1조/2_데이터수집_저장/06_budget_rnd` 폴더(23개 파일)와 팀 DB(`defense_dashboard`)를 2026-09-17에 대조한 결과다.
> 표기: **확인됨**(직접 조회·열람) / **제안** / **미확인**을 구분했다. 맨 아래 「결정·확인이 필요한 것」에 답을 주면 다음 작업으로 넘어간다.

## 0. 요지

- 폴더 자료 대부분은 HS6·FSC·NSN 같은 **품목 키가 없다.** 공통 키는 **연도**뿐이라, `v_review_list`의 품목군 행에 직접 붙지 않고 배경 ⓪·④(연도 축)에 붙는다.
- 붙는 방식은 세 단계다: ① 이미 붙은 것(열린재정 12파일) ② 연도 축으로 바로 붙는 것(작은 표 6개) ③ 품목군까지 붙일 수 있는 후보(목록 2개 + 국산화율 1개).
- 어제 "불가"로 판정한 **"관련 R&D 예산" 열은 여전히 불가**다(과제별 금액 열이 없음). "관련 R&D **과제 수**(키워드 후보, 잠정)"로 재정의하면 가능하다.

## 1. 이미 붙어 있는 것 (확인됨)

| 파일 | DB | 상태 |
|---|---|---|
| `openfiscal_dapa_program_budget_<연도>` 12개(회계연도 2016~2027) | `raw_openfiscal_program_budget` → `v_budget_rnd_yearly` | 적재 완료 2,860행. 연도별 `COUNT(*)`로 직접 확인(2016~2019 879행 + 2020~2027 1,981행) |

교차 확인: `v_budget_rnd_yearly.localization_gov_100m` 2021~2024년 값(886.4 / 1,691.1 / 1,845.1 / 1,232.7억)이 드라이브 `localization_support_budget.csv`(886 / 1,691 / 1,845 / 1,232억)와 일치한다. README의 교차 검증이 DB에서도 재현된다.

## 2. 아직 안 붙은 것

DB 테이블 44개·뷰 20개 중 방위사업통계연보·핵심기술 과제·특허에 해당하는 것은 없다(확인됨).

### (가) 연도 축으로 바로 붙는 것 — 작은 표 6개

| 파일 | 행 수 | 기간 | 쓰임 |
|---|---|---|---|
| `procurement_dom_foreign.csv` | 9 | 2016~2024 | 국내·국외 조달 **집행액 실적**. 조달계획(A7)은 계획, 이것은 집행이라 나란히 놓을 수 있다(합산 금지). 배경 ⓪에서 가장 쓸모가 크다 |
| `defense_rnd_budget.csv` | 10 | 2016~2025 | 국방 R&D 예산, 국방비·국가 R&D 대비 점유율 |
| `localization_support_budget.csv` | 15 | 2010~2024 | 부품국산화 지원예산·신규 승인과제·매출액. 열린재정은 2021년(사업 신설)부터만 있어 앞 구간을 채운다 |
| `dapa_core_tech_rnd_budget_기준20241231.csv` | 13 | 2012~2024 | 핵심기술 연구개발 예산·과제 수(신규·계속·완료·중단) |
| `dapa_basic_research_budget_기준20241231.csv` | 미확인(열지 않음) | 2012~2024(README 기준) | 기초연구 예산·과제 수 |
| `localization_rate_by_field.csv` | 15 | 2013~2023 | 분야별 완성장비 국산화율. (나)에서 다시 다룬다 |

**제안**: 파일마다 테이블을 만들지 않고 세로형 테이블 하나에 모은다. 전부 60여 행이다.

```
raw_dapa_yearbook_stat(source_file, yearbook_edition, table_no, stat_year, metric, value, unit)
  → v_budget_context_yearly  -- 연도 기준으로 v_overseas_plan_yearly · v_budget_rnd_yearly 와 나란히
```

그러면 배경 ⓪·④ 화면이 "조달계획(계획) / 조달 집행(실적) / R&D 편성(예산)" 세 줄로 채워진다. 세 값은 기준이 달라 합산·비율 계산은 하지 않는다.

### (나) 품목군에 붙일 수 있는 후보 — 3개

| 파일 | 연결 고리 | 가능한 것 | 한계 |
|---|---|---|---|
| `add_tech_transfer_patent_기준20241231.csv` | `기술분야` 3단 분류(예: `센서-레이더 센서-…`, `정보통신-전자전-…`) | 기술분야 중분류 → 화이트리스트 `category` 대응으로 "품목군별 기술이전 특허 N건" | 대응표를 새로 만들어야 하고 팀 판단이 들어간다 |
| `krit_core_tech_project_기준20241231.csv` | 한글·영문 키워드, 사업 개요 | 키워드 일치로 "품목군별 관련 R&D 과제 수" 후보 | **과제별 금액 열 없음.** 키워드 일치는 후보 선정일 뿐이다 |
| `localization_rate_by_field.csv` | 분야(통신전자·항공·유도·광학 등) | 화이트리스트 `system_family`와 분야 수준에서 나란히 놓기(예: 항공 52.5%로 최저, 2025년보 2023년 값) | 완성장비 조달가격 기준이라 **부품 원산지는 반영되지 않는다**(README 명시). 연보 판마다 수치가 달라 판을 섞어 시계열로 잇지 않는다 |

(나)는 키워드·분류 대응이라 모두 "후보"다. 적용하면 연결률·미연결 건수·다중 일치 건수를 함께 보고한다(CLAUDE.md 「정제·연결·해석」).

## 3. 진행 순서 (제안)

1. 파일을 `data/raw/budget/`에 내려받고 `meta_dataset`에 출처·SHA-256·연보 판을 기록한다.
2. (가)를 먼저 적재한다: `db/alter_2026-09-17_yearbook_stat.sql` + `v_budget_context_yearly`.
3. (나)는 품목군 대응표(B-1) 확정 뒤에 한다. 특허 기술분야 대응은 같은 회의에서 함께 결정하면 된다.

역할: CSV 정제·적재 노트북은 사용자 영역, 테이블·뷰 설계와 검증은 Claude. Claude의 DB 연결은 읽기 전용이라 alter 실행은 사람이 한다.

## 4. 결정·확인이 필요한 것

| # | 항목 | 내용 | 상태 |
|---|---|---|---|
| 1 | **`46370` 중복** | `procurement_dom_foreign.csv` 2020년 국외조달 = 46,370억, `defense_rnd_budget.csv` 2024년 국방 R&D = 46,370억. 서로 다른 표인데 다섯 자리가 같다. 우연일 수 있으나 PDF 전사값이라 옮기다 틀렸을 가능성이 있다. 연보 2025년판 3-1-1·1-3-2와 대조 필요 | **미확인** |

| 5 | (가) 세로형 테이블 1개 방식 | 파일별 테이블 대신 `raw_dapa_yearbook_stat` 하나로 모으는 안에 동의하는지 | 결정 필요 |

## 5. 확인 방법 (재현)

```sql
-- 열린재정 연도별 적재 건수(합 2,860)
SELECT fiscal_year, COUNT(*) FROM raw_openfiscal_program_budget GROUP BY fiscal_year ORDER BY 1;
-- 부품국산화 예산 교차 확인
SELECT fiscal_year, localization_gov_100m FROM v_budget_rnd_yearly WHERE fiscal_year BETWEEN '2021' AND '2024';
```

드라이브 파일은 `README.md`, 작은 CSV 5개 전체, 큰 목록 2개(`krit_core_tech_project`, `add_tech_transfer_patent`)의 앞부분(열 구조)만 열람했다. 큰 목록 2개의 전체 행 수는 세지 않았다(미확인). 연보 PDF 2개는 열지 않았다.
