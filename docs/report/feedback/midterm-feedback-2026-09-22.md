## 5. 범위 선정 — 1,003개에서 13개까지 전부 보이기

메모 「어떻게 1,003개가 나왔는데 어떻게 잘랐는지 / HS 코드의 85~90이 뭔가 / 통과보다는 범위 선정 자세하게 / 7개의 소자조차 근거랑 판단」. 요약본 §3과 완전히 같은 지적이다.

### 5-1. HS 코드부터 설명한다

메모에 「85~90」이라고 적혔지만 실제로 쓰는 것은 **연속 구간이 아니라 4개 류**다. 이것부터 틀리게 전달됐다는 뜻이므로 슬라이드에 못 박는다.

| 류 | 이름 | 이 프로젝트에서 |
| --- | --- | --- |
| 84 | 기계류 | 반도체 제조장비(848620) 등 배경 자료 |
| 85 | 전기기기·전자부품 | **주력** — 집적회로(8542), 개별소자(8541), 레이더·통신기기(8525·8526·8529) |
| 88 | 항공기·우주선 | 항공기 부분품(880730) 배경 자료 |

## 6. 데이터 파이프라인 — 순서와 DB 설계

메모 「슈집 / 전처리 하고 db 구성 / db 파이프라인 / 수집 전처리 적재」. 요약본 §4와 같다.

### 6-1. 말하는 순서를 바꾼다 (반영 쉬움)

지금 대본은 「4장 수집·저장 → 5장 전처리」라서 **저장이 전처리보다 먼저** 나온다. 이것이 「수집 후 바로 무분별한 DB 저장」으로 읽혔다. 최종본은 **수집 → 전처리 → 적재** 순으로 장을 재배치한다.

### 6-2. 수집·전처리를 상세화한다

- 수집: API별 기간·컬럼 구성·데이터 타입 명시. 재료는 `docs/report/data/` 명세서와 9/22 생성한 데이터 명세서 xlsx에 이미 있다.
- 전처리: 결측·중복·단위/코드 표준화를 **표 한 장이 아니라 단계별 처리 내역**으로 분기. 검증 기준(원본 = 정제 + 제외, 차이 0)과 제외 17행의 사유는 그대로 쓴다.

### 6-3. 「원본을 통째로 RDB에 넣지 말라」 — **결정·실행 완료(2026-09-22)**

> 아래 「구조를 바꾸지 않는다」 제안은 **채택되지 않았다.** RDS `raw_` 23표를 삭제했고 원본은 `data/raw/` 파일 + `meta_dataset` 명세로만 둔다(`professor-feedback-2026-09-22.md`, 09-23 사용자 재확인). 아래는 당시 제안 기록이다.

요약본 §4의 지적이다. 현재 구조는 `raw_` → `clean_` → `v_`로 RDS에 3층을 모두 두고 있다(테이블 56 + 뷰 31).

- **제안**: 구조를 지금 바꾸지 않는다. 제출이 10/2이고, raw 계층은 재현성 근거(원본 행 수 = 정제 + 제외)로 쓰이고 있으며, 1만 건 요건 2종도 raw 기준으로 센다.
- 대신 **설명과 화면에서 계층 역할을 분명히 한다**. 「원본은 검증·재현용으로 보존하고, 분석과 화면은 정제본과 뷰만 본다」를 ERD 슬라이드에 명시한다.
- 최종 보고서에 「오브젝트 스토리지에 원본을 두는 방식이 정석이나 학습·검증 목적으로 DB에 보존했다」는 한 줄을 남기면 지적에 답이 된다. (**결정 필요** — §9)

## 7. 분석 — 4축을 하나씩 펼쳐서

메모 「분석의 큰 주제 하나씩 펼쳐서 설명 / 분석 범위 - 데이터」. 팀 정리본 §5의 4축을 그대로 쓰되, 실측으로 **가능 여부를 확인**했다.

### A. 품목 — HS6에서 HS10으로 내려가기

**가능(확인됨)**. `fact_customs_monthly`에 `hs10` 열이 있고 294,174행 · HS6 24개 · **HS10 211개** · 2016~2026년이다. HS6 총액에서 멈추지 말고 HS10 구성·수입/수출·무역수지·증감·상대국까지 내려간다.

> 주의: HS10 세분류 이름에 「군용」이 있어도 그 행이 군납이라는 뜻은 아니다. 용도 세분류일 뿐이다.

### B. 국가 — 순위가 아니라 구조

품목마다 상대국 구성이 어떻게 다른지. HS6 × 국가 히트맵, Top N + 기타, 순위 변화. HHI와 1위국 점유율은 **정보가 거의 겹치므로 한 화면에 둘 다 올리지 않는다**(팀 정리본 §2-2). 집중도는 집중도일 뿐 위험·의존도가 아니다.

### C. 국산화 — 제목에 있는데 약하다

국산화개발품목(B2)을 FSG 58·59·60 / FSC / 사업 / 업체 / NSN 축으로. 실측: 고유 25,025행 · 사업 28개 · 전자군(58·59) 2,717행.

> 주의: 품목 **개수는 국산화율이 아니다.** 공개 자료로 국산화율·목표 달성률은 산출하지 않는다.

### D. 적용장비·조달 — 가장 덜 쓰고 있던 축

**가능(확인됨)**. `clean_dapa_overseas_plan_api` 13,615행에 적용장비명·군·FSC가 있다.

| 항목 | 실측 |
| --- | --- |
| 전체 행 | 13,615 |
| 적용장비명 고유 | 842종 (장비코드 913) |
| 적용장비명 결측 | 2,018행 (14.8%) |
| 군별 | 육군 7,404 · 해군 5,254 · 공군 717 · 해병대 212 · 국직 18 · 미확인 10 |
| 전자 계열(FSG 58·59·60) | 2,267행 |

**이 축이 「어떤 부품이 어떤 무기체계에 쓰이는가」에 답하는 두 번째 경로다.** 국산화개발품목(B2)은 지상 기동·화력 28개 사업에 갇혀 있지만, 이 데이터는 육·해·공을 모두 덮는다. 상위 장비는 헬리콥터 500MD토우기 1,833행, 교량가설 보트 635, 다목적굴착기 459 순이다.

> 주의: 이 데이터에는 **공급 국가가 없다.** 업체명·장비명으로 공급국을 추정하지 않는다. 표준화 열(`equipment_name_std`)은 439행에만 채워져 있어 **원문 장비명 기준으로 집계**해야 한다(표준화 확대는 별건).
