# 중간 발표 전 총정리 — 흐름 · 방법 · 용어 · 예상 질문 (2026-09-22 발표용, 09-21 회의 결정 M1~M8 반영)

팀원 누구나 이 문서 하나로 "우리가 무엇을 어떻게 했는지"를 설명할 수 있게 모았다. 수치는 저장소 문서 · 노트북 실행 결과 · 팀 보고서(09-19, 09-20)에서 옮겼고, 09-21 회의(M5)로 분석 대상이 19 → **13개**로 바뀐 만큼 §4의 수입액 · 집중도 건수는 RDS 뷰로, §5의 EDA 검정 · 상관은 노트북 재실행으로 2026-09-22 모두 13개 기준으로 다시 냈다. 더 깊은 근거는 각 절 끝의 「어디를 보면 되나」를 따라간다.

## 1. 한 장 요약

- **무엇을 만드나**: 「국방 핵심 전자부품 **수출입 및 국산화 현황** 대시보드」(09-21 6차 회의 M1 확정. 「의존도」 · 「모니터링」은 제목 · 화면에 쓰지 않는다) — 부제 「공식 분류 · 통제표로 고른 전자부품 품목군 · 공개 데이터 기반 현황 대시보드」(M8). 공식 분류 · 통제표 규칙으로 고른 품목군 **13개**(수집 24개)가 어느 나라에서 들어오고 나가는지(수입 · 수출 동등 배치), 어떤 무기체계에 쓰이며, 국산화 개발이 어디까지 왔는지(건수)를 공개 자료로 보여 준다.
- **하지 않는 것**: 위험 예측 · 위험 지수 · 조기경보, 「의존도」 · 「국산화율」 산출, HS ↔ 군급(FSC) 연결(09-21 폐기), 인과 판단.
- **지금 어디까지**: 수집 · 저장 · 전처리 **완료**(운영 DB AWS RDS, 테이블 60 + 뷰 31, 모든 묶음 검산 차이 0) → EDA **1차 완료**(노트북 2종) → 화면 **뼈대**(홈 + 6페이지) + 화면 명세 `app/specs/`(팀원 각자 Figma 디자인 대기, M3) → 남은 것: EDA를 13개 기준으로 재실행, Figma → 화면 구현, 명세서 · 설계서, 시연 영상, PPT.
- **일정**: 10/2 산출물 제출, 10/5 PPT, 10/6 발표(20분 + Q&A 10분).

## 3. 데이터가 흐르는 길과 방법

```
기준표(hs_whitelist.csv) → ① 수집 → data/raw/(원본 동결) → ② 적재 → RDS raw_ → ③ 정제 → clean_ → ④ 뷰 v_ → ⑤ 앱
                                                  └ ref_(참조 · 규칙) · meta_(출처 · 건수 · 열 사전 · 적재 이력)
```

### ① 수집 — 네 가지 방법

| 방법 | 대상 | 어떻게 |
|---|---|---|
| **OpenAPI 호출** | 관세청 품목별 · 국가별 수출입실적(15100475) | `scripts/fetch_customs.py --all-countries`: HS6 × 연도마다 1번 호출(국가 생략 = 전체 국가), 24개 품목군 × 2016~2026 → 파일 24개, **294,420행**. 서비스 키는 `.env`에만 둔다 |
| OpenAPI 호출 | 관세청 시군구별 수출입실적(15134343) | `scripts/fetch_customs_region.py`: HS6 × 시도 × 연도, **273,586행**(2026-09-21 RDS `raw_customs_region` 적재. M7로 「과천시 소재 수입자 비중(방위사업청 소재지), 추정」 KPI 채택 — 중간 발표에는 넣지 않음) |
| OpenAPI 호출 | 방위사업청 국외 조달계획 품목 단위(15158418) | 13,615행. 방사청 `_GW` 입찰 · 계약 API 3종은 **하루 100호출 제한**이라 쓰지 않고 파일데이터로 대체 |
| **파일데이터 내려받기** | 방위사업청 계약정보(43,112행) · 입찰 · 조달계획 · 국산화개발품목 · 군급분류집 · 방산업체 지정현황, 관세청 HS부호, 무역안보관리원 HSK 연계표, 열린재정 예산, KOSIS 통계표 | 공공데이터포털 · 각 기관에서 CSV/XLSX. 방사청 CSV는 **cp949** 인코딩 |

원칙: **건수는 포털 표시가 아니라 실제 내려받아 파서로 센 값**으로 말한다. 원본은 `data/raw/`에 두고 수정하지 않는다(훅으로 수정 차단).

### ② 적재 — `scripts/load_db.py`

- 순서 `--ref`(참조표 · 열 사전) → `--raw`(원본 22표) → `--fact`(관세청 월별 사실표). `--dry-run`으로 DB 없이 헤더 · 건수부터 대조한다.
- **열 사전(`db/column_dict.csv`, 823행)** 으로 CSV 한글 헤더를 순서대로 대조한 뒤 영문 열에 넣는다. 헤더가 다르면 멈춘다.
- pymysql `executemany` 2,000행 배치. DB가 **STRICT 모드**라 열 길이 초과는 조용히 잘리지 않고 오류가 난다(실제로 열 밀림 원본을 이렇게 찾았다).
- 파일마다 `meta_load_log`에 건수가 자동 기록된다. 재적재는 스크립트가 하지 않는다(비어 있지 않으면 건너뜀 — 실수로 두 번 넣는 것 방지).

### ③ 정제 — 노트북 6개 + alter 파일

- 노트북 `notebooks/clean_*.ipynb`가 raw를 읽어 clean 표를 채운다. 묶음 P1 관세청 · HS / P2 예산 / P3 국외조달 / P4 국내조달 / P5 KRIT · KOSIS.
- 규칙(`docs/reference/data-cleaning-rules.md`): 타입 변환(날짜 → DATE, 금액 → 숫자 + 단위 접미사 `_krw` · `_usd`), 자리표시(`-`, `*`, 빈칸) → **NULL**, 개인정보 열 제외, 모든 clean 행에 `raw_row_id`(원본 추적), 값 **추정 금지**(모르면 NULL · 「미확인」).
- **행을 뺄 때는 지우지 않고 기록**한다: `clean_excluded_row`에 사유 코드(KEY_CONFLICT 키 충돌 1 · COL_SHIFT 열 밀림 4 · PLACEHOLDER 테스트 12 = 17행).
- **검산**: 모든 묶음에서 `raw 행 수 = clean 행 수 + 제외 행 수`, 차이 0.
- 스키마 변경은 `db/alter_<날짜>_<주제>.sql`로만 하고 `scripts/apply_alter.py --twice`로 적용한다 — 두 번째 실행에서 0행이 나와야 통과(**멱등**).
- 결측은 77열을 전수 판정했다: 구조적 31 · 원본 결측 36 · 의도된 NULL 10. 화면 표기 어휘는 「미기재」 · 「판단 보류」 · 「해당 없음」.
- clean 표는 **분석용**이라 raw에 그대로 있는 저분산 원본 속성 열(최빈값 ≥ 95%, 뷰 · 앱 · 규칙표 · 키가 안 쓰는 것)은 뺐다(09-21 규칙 #13, 5표 20열 — 예: 국외 입찰결과의 발주기관 · 계약방법 · 입찰방법 · 낙찰방법). 정제 산출 플래그 · 판단 속성 · 금액 가중으로 의미 있는 열은 유지.

### ④ 뷰 · ⑤ 앱

- 화면은 표를 직접 읽지 않고 **뷰(`v_`) 31개**를 읽는다(예: `v_hhi_hs6_year` 품목군 × 연도 HHI). 집계 정의가 SQL 한 곳에 있어 EDA · 화면 숫자가 어긋나지 않는다.
- 앱은 Streamlit. 읽기 전용 계정 `app_ro`로 접속한다. 공개 주소 https://defense-trade.streamlit.app (공동작업 저장소 `main`에 push하면 자동 배포).

## 5. 용어 사전

### 도메인

| 용어 | 뜻 |
|---|---|
| **HS 코드** | 국제 통일 상품 분류. 6단위(HS6)까지 세계 공통, 한국은 10단위(HS10, HSK)로 세분. 우리는 HS6를 「품목군」, HS10을 「세부코드」라 부른다 |
| HS 84 · 85 · 88 · 90류 | 기계 / 전기 · 전자 / 항공기 / 광학 · 정밀기기. 선정 규칙을 적용한 범위 |
| **전략물자 · 이중용도** | 무기 개발에 쓰일 수 있어 수출이 통제되는 품목. 민수 · 군수 겸용이 「이중용도」. HSK 연계표가 HS 코드와 통제번호를 잇는다(규칙 R3) |
| **FSC · FSG (군급)** | 미 연방 보급 분류. FSC 4자리, 앞 2자리가 FSG. **FSG 58 통신 · 탐지, 59 전기 · 전자 구성품, 60 광섬유**가 우리 범위 |
| **NSN · NIIN** | 국가재고번호 13자리 = FSC 4 + NIIN 9(국가코드 2 + 일련번호 7). 군수품 하나하나의 번호 |
| HS ↔ FSC | 공식 연계표가 **없다**. 09-21 후보 대응표(HS6 ↔ FSC4)까지 폐기 · DB 삭제. 두 축을 어떤 수준에서도 엮지 않고 나란히 놓는다 |
| 방위사업청(DAPA) · KRIT | 무기 조달 기관 · 국방기술진흥연구소(부품국산화 개발 지원사업 공고) |
| 국외조달 · 국내조달 | 해외 업체 / 국내 업체와 맺는 군수 계약. 국외 조달계획 자료에는 **공급 국가 열이 없다** |
| 국산화개발품목 | 방위사업청이 공개한, 국산화 개발이 완료 · 진행된 부품 목록(군급 · 사업 단위). 「국산화율」이 아니다 |
| 수의계약 | 경쟁 없이 특정 업체와 맺는 계약. 사유 조문이 원본에 있다 |
| 계약 차수 | 같은 계약의 변경 회차(00, 01…). 계약 단위 금액은 **최종 차수의 총계약금액** |

| **HHI** | 점유율(%) 제곱의 합, 0~10,000. 한 나라가 100%면 10,000. 2,500은 고집중 참고선(미 법무부 2010 합병 심사 기준에서 빌린 값 — 무역에 대한 공식 기준은 아님) |
| 50% 참고선 | 산업부 「산업 공급망 3050 전략」의 특정국 의존 50% 기준 |
| 부분연도 · 정부안 | 2026년은 1~8월뿐이라 연간 비교에서 제외 · 2027년 예산은 확정 전 정부안이라 라벨 표시 |
| 민수 포함 | 관세청 통계는 국가 전체 교역(민항 · 조선 · 자동차 포함). 「방산 수입 집중도」도 「군수 의존도」도 **아니다** — 「국가 전체 수입(민수 포함) 기준」이라 쓴다 |

### 통계 (EDA)

아래 검정 수치는 `notebooks/eda_customs.ipynb`를 **13개 기준으로 재실행한 2026-09-22 결과**다(09-19 1차는 19개 기준). 19개 기준 옛값은 괄호에 적었다.

| 용어 | 뜻 · 우리가 쓴 곳 |
|---|---|
| 왜도 | 분포의 치우침. 수입액 · 계약금액이 극단적으로 치우쳐(24.2 · 94.7) 로그 척도 · 비모수 검정을 기본으로 했다 |
| 정규성 검정(Shapiro-Wilk) | 정규분포인지 확인 → 통과하면 t 검정, 아니면 비모수. 대응표본은 **두 값의 차이**가 정규인지 본다. 우리 결과: H1 차이는 기각(p<0.0001) → Wilcoxon, H2 차이는 통과(p=0.68) → 대응 t |
| 모수 vs 비모수 · 순위 | 모수 검정은 평균을 비교해 큰 값 하나(반도체 336억 달러)에 끌려간다. 비모수는 값을 **순위**로 바꿔 비교하므로 아무리 큰 값도 "1등" 한 자리일 뿐 — 치우친 자료에 강하다 |
| 대응 t · **Wilcoxon 부호순위** | 같은 대상의 두 값 비교(모수 · 비모수). Wilcoxon 계산: ① 대상마다 차이(후 − 전) ② 부호를 떼고 크기 순위 ③ 증가 쪽 순위 합과 감소 쪽 순위 합 비교 — 차이가 없다면 두 합이 비슷해야 한다. **H1** 같은 품목군의 연평균 수입액 2021~25 vs 2016~20: Wilcoxon, n=12, p=0.339, 효과크기 r=+0.28 → 유의하지 않음(증가 6개 · 감소 6개가 상쇄 — 반도체 3개는 모두 +69~89%, 항행 · 통신 계열 6개는 감소. 옛값 n=18 · p=0.196). n이 13이 아닌 12인 이유: `880730`은 HS2022 신설 코드라 2016~20 값이 없어 제외. **H2** 같은 품목군의 수입 HHI vs 수출 HHI: 대응 t, n=19, p=0.022, r=+0.53, 중앙값 2,533 vs 1,892 → 수입이 더 몰려 있다(유의) |
| **Mann-Whitney U** · Kruskal-Wallis | 서로 다른 두 집단 · 세 집단 이상 비교(비모수). 두 집단을 섞어 순위를 매긴 뒤 한 집단의 순위가 위쪽에 몰렸는지 본다. **H3** 수입 HHI 반도체 vs 그 외: U=11, p=0.573, r=−0.27 → 유의하지 않음(옛값 p=0.368) |
| **카이제곱 독립성 검정** · Cramér's V | 범주 × 범주의 관련성 · 그 크기(0~1). 예: 업무구분 × 수의계약 여부, V=0.09(작음) |
| **Spearman 상관** | 두 변수를 각각 순위로 바꾼 뒤 그 순위끼리 구한 상관 ρ(−1~+1). Pearson은 **직선** 관계 · 극단값에 민감, Spearman은 **단조** 관계(오르면 같이 오르는가) · 극단값에 강함. n=13에서는 \|ρ\| ≥ 약 0.55여야 유의(19개였을 때는 0.46). 우리 결과: 수입 HHI × 1위국 점유율 ρ=+0.97(HHI에 1위국 점유율의 제곱이 들어가므로 사실상 같은 정보 → 화면에는 하나만), log 수입액 × log 수출액 ρ=+0.96(옛값 0.93), 무역수지비 × 수입거래국수 ρ=+0.83, 수입액 × 수입 HHI는 유의한 상관 없음 |
| p값 · 유의수준 0.05 | 차이가 없다고 가정할 때 이런 결과가 나올 확률. **"유의하지 않음" ≠ "차이 없음"**(표본 13개라 검정력이 더 낮다 — H2가 그 예로, 19개에서 p=0.022로 유의했으나 13개에서는 p=0.065로 넘지 못하고 효과크기는 r=+0.51로 그대로 중간 이상이다) |
| 효과크기 | 차이의 크기. n이 수만 건이면 p는 늘 작으므로 효과크기로 판단. 노트북은 대응 검정에 r = Z/√n, Mann-Whitney에 순위이연 상관을 쓴다(관례상 0.1 작음 · 0.3 중간 · 0.5 큼) |
| 다중비교 보정(Bonferroni) | 검정을 여러 번 하면 우연히 유의해질 확률이 커져 기준을 나눔(0.05 / 3 = 0.017) |
| 수준 상관 vs 변화율 상관 | 둘 다 오르는 시계열은 상관이 높게 나온다(r=0.85). 전년동월비로 바꾸면 r=0.05(n=115, p=0.56) → 공통 추세일 뿐. 이 r은 Spearman이 아니라 **Pearson** 값이다(반도체 월 수입액 × 전자부품 생산지수) |
