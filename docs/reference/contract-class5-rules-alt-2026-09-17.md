# 국내조달 계약정보 5분류·속성 규칙 — 대안 초안 B (2026-09-17)

**상태: 초안(Claude 작성, 팀 결정·표본 검수 전). 서버·노트북 미적용.** 기존 초안(`contract-class5-rules.md`)을 참고하지 않고 팀 서버 `raw_dapa_contract` 43,112행을 직접 실측해 독립적으로 설계했다. 두 초안을 비교해 하나를 고르거나 합치는 것은 팀 결정이다. 기계가 읽는 규칙표는 `data/reference/contract_class5_rules_alt.csv`.

목표 열(`db/schema.sql` `clean_dapa_contract`): `class5` · `is_electronic` · `is_part` · `is_defense_related` · `matched_keywords` · `evidence` · `review_status` · `contract_group` · `category_link_status`. 정제 원칙은 `docs/idea-review.md` §5, 건수·표현 규칙은 CLAUDE.md를 따른다.

## 0. 설계 방침 — 순서형 첫 일치가 아니라 「신호 독립 판정 + 충돌표」

키워드를 위에서부터 훑어 첫 일치로 확정하는 방식은 순서를 바꾸면 결과가 바뀌고, 왜 그 분류가 됐는지 나중에 되짚기 어렵다. 이 초안은 네 단계로 나눈다.

1. **정규화** — 계약명에서 부대·시설 명칭 토큰을 지운다. 「전차대대 OA비품」의 「전차」, 「화생방훈련장 신축」의 「화생방」이 무기체계로 잡히는 오탐을 원천에서 막는다.
2. **신호 판정** — 텍스트 신호 6개(A·M·R·W·E·P)와 구조 신호 4개(S_DAPA·S_REASON·S_LOG·S_SVC)를 **서로 독립으로** 참/거짓 판정한다. 신호는 전부 기록한다(`matched_keywords`).
3. **분류 결정** — 분류 신호군 4개(A 행정 / M 군수물자 / R 정비 / D 방산)의 조합으로 `class5`를 정한다. 하나만 켜지면 그 분류, 둘이면 §4 충돌표, 셋 이상이면 `판단 보류`.
4. **속성·품목군** — `is_electronic`·`is_part`·`is_defense_related`는 분류와 별개로 신호에서 직접 채우고, 전자 후보에만 `contract_group`을 붙인다.

장점: 순서 의존이 없고, 충돌 건수가 그대로 검수 대상 목록이 된다. 한계: 계약명은 품명이 아니라 계약 제목이라 신호가 없는 행이 많다(§6, 판단 보류 35.8%). 이것은 숨기지 않고 화면에 그대로 보인다.

## 2. 0단계 — 정규화(마스킹)

계약명에서 아래 접미사로 끝나는 토큰(붙어 있는 한글·영문·숫자 포함)을 공백으로 바꾼 뒤 신호를 판정한다. 원문은 `raw_`에 있으므로 정보 손실이 아니다.

```
[가-힣A-Za-z0-9]*(대대|여단|사단|군단|부대|훈련장|훈련단|비행단|전대|사령부|근무지원단|탄약고|무기고|탄약창|정비창|정비공장|생활관|소초|중대|연대|포상|포병|훈련대)
```

- 실측: 43,112행 중 **9,003행**이 마스킹으로 바뀜.
- 효과 예: 「81전차대대 도로포장 공사 관급자재」→ 「 도로포장 공사 관급자재」(행정), 「2탄약창 이글루 탄약고 신축공사」→ 신축공사(행정), 「1무기지원대대 신축정비공장 비품」→ 비품(행정).
- 알려진 부작용: 「부대조달 부식」의 「부대」가 지워지지만 「부식」이 남아 판정에 영향 없음. 「포병」 마스킹이 「포병탐지레이더」의 「포병」을 지워도 「레이더」가 남는다. 검수에서 부작용 사례가 나오면 접미사 목록을 줄인다.

## 4. `class5` 결정표

분류 신호군: **A** = A, **M** = M, **R** = R_strong ∨ R_weak, **D** = W ∨ S_DAPA ∨ S_REASON ∨ (P ∧ S_LOG).

| 켜진 신호군 | `class5` | 근거·검수 표본 |
|---|---|---|
| 없음 | 판단 보류 | 「~등 N종 구매」「소모품」처럼 계약명에 품목 정보가 없음 |
| A만 | 일반 행정·운영 | — |
| M만 | 일반 군수물자 | — |
| R만 | 정비·기술지원 | — |
| D만 | 방산 장비·부품 후보 | — |
| A + M | S_SVC이거나 A_fac이면 **행정**, 아니면 **군수물자** | 「피복 세탁 용역」→행정, 「정비/취사피복 제조」→군수물자, 「폐타이어 수송처리」→행정 |
| A + R | 일반 행정·운영 | 승강기 유지관리, 소방시설 점검, 시설 보수 |
| A + D | S_DAPA면 **방산 후보**, 아니면 **행정** | 「전차 주간표적지 세트」·「탄약고 제초」는 행정. 방사청의 「활주로 진공 청소차」「이동식 에어컨(5톤 밴용)」은 장비 → 방산 후보 |
| M + R | R_strong이면 **정비**, 아니면 **군수물자** | 「의무장비 외주정비」→정비, 「정비피복 구매」→군수물자 |
| M + D | P면 **판단 보류**, 아니면 **군수물자** | 「일반공구류(천무 창정비용)」「25년 방한화」(방사청)→군수물자, `is_defense_related=예` 유지. 「취사기 트레일러 탑재식 및 수리부속류」→보류 |
| R + D | 정비·기술지원 | 「K2전차 엔진 외주정비」「천궁2 창정비요소개발」 |
| 셋 이상 | 판단 보류 | 159행. 전부 검수 대상 |

## 7. 검수 설계 (사용자 몫, 규칙 확정 전 필수)

1. **층화 표본**: class5 5개 × E 여부 2개 = 10층에서 층당 30행(작은 층은 전수). 약 300행.
2. **충돌 우선**: 두 신호군 충돌 3,005행 중 각 조합에서 20행씩 별도 검수. §4 충돌표의 해소 방향이 틀리면 표를 고친다.
3. **보류∧전자 1,988행**: 화면 ②의 후보 테이블에 「보류·전자」 필터로 노출한다. 이 층에서 W 없이 방산으로 판단되는 건이 많으면 W 키워드를 늘린다.
4. **기록**: 검수한 행은 `review_status='검수완료'`, `evidence`에 「검수: 확정/오탐/사유」. 표본 정확도는 층별로 보고하고 전체로 확대 추정하지 않는다.
5. **재현**: 규칙 CSV의 `rule_version`을 올리고, 버전별 class5 분포를 `meta_load_log`에 남긴다.

## 8. 알려진 한계·오탐

- 계약명이 「~등 N종」(6,238행)이면 대표 품목 하나만 보인다. 보류가 많은 이유.
- 「함정」은 「함정 승강기」「함정 매트리스」처럼 장소로도 쓰인다. A+D 충돌표가 행정으로 돌리지만 A 키워드가 없으면 방산 후보로 남는다(검수 층 4).
- 「수리」는 「수리부속」을 제외했으나 「수리창」은 마스킹에 의존한다.
- 「공구」는 「1공구·2공구」(공사 구역)를 숫자 앞 lookbehind로 뺐다. 「공구단지」 같은 예외는 미확인.
- S_LOG는 부서명 문자열 일치라 「해군군수사령부」가 사는 냉난방기도 P가 있으면 D가 켜진다. P가 「~류」로 끝나는 일반 물품(「가스켓류」)도 포함되므로 P∧S_LOG 1,739행은 검수 층 2에서 확인한다.
- 정규식은 MariaDB `REGEXP`(PCRE)로 실측했다. Python `re`는 lookbehind `(?<![0-9])`·lookahead `(?!부속)`를 같은 문법으로 지원하지만, 노트북에서 실행한 분포가 이 문서의 표와 같은지 먼저 대조한다.

## 9. 기존 초안과의 관계

기존 `contract-class5-rules.md`는 읽지 않고 작성했다. 두 초안의 class5 분포를 같은 원본에서 나란히 내고, 차이 나는 행을 검수 표본에 넣어 어느 쪽 규칙이 맞는지 보는 것을 권한다. 규칙 정의는 팀이 하나로 확정한 뒤 `data/reference/`에 하나만 남긴다.
