### 7-2. `civil_mix` 도출 규칙 (팀 규칙, 문턱값 조정 가능)

1. `mil_hs10_share`가 있으면 → `< 1%` **높음** / `1~20%` 중간 / `≥ 20%` 낮음
2. 없고 `aero_hs10_share`가 있으면 → `< 20%` 높음 / `20~80%` **중간** / `≥ 80%` **낮음**
3. 둘 다 없고 `hsk_control_hs10_ratio`가 있으면 → 문턱값 미정(적재 후 결정), 그때까지 NULL
   - **(2026-09-19) 지표는 들어왔으나 문턱값은 여전히 미정**이다. `v_civil_mix_rule`의 `civil_mix_basis`가 15개 품목군에서 `판단불가` → `hsk`로 바뀌었지만 `civil_mix_rule` 라벨은 **NULL 그대로**다(24개 중 11개가 비율 100%라 구분이 안 된다). 저장 열 `ref_hs_whitelist.civil_mix_basis`는 2026-09-16 스냅샷이라 `판단불가`로 남아 있다 — 뷰와 스냅샷이 다른 점은 **잠정**이며 팀 확인 뒤 정리한다(`docs/db/schema-change-log.md` §7).
4. 어느 것도 없으면 → NULL, `civil_mix_basis = '판단불가'`

문턱값 1 / 20 / 80%는 "군용 전용 신고가 1% 미만이면 수입 흐름은 사실상 민수", "항공기용이 80% 이상이면 범용 소비재 흐름이 아님"이라는 팀 규칙이며 통계적 근거가 있는 경계가 아니다. 규칙은 **"정량 근거로 도출"** 이지 "정량적으로 검증"이 아니다.

**HS6 공식 명칭 보정 규칙(2026-09-19 실측, 잠정)** — S1' 「HS부호 단위별 품목명」(15130660)의 코드 길이 혼재는 **앞자리 0 누락이 아니다**:
1. 각 시트에 `0`으로 시작하는 코드가 그대로 있다(전체 1,601행: 02단위 9 · 04단위 86 · 06단위 296 · 08단위 109 · 10단위 1,101). 0이 잘렸다면 01~09류가 남아 있을 수 없다.
2. 5자리는 HS **한 줄(one-dash) 중간 수준**이다 — `85423` = 「전자집적회로」 아래에 `854231`·`854232`·`854233`·`854239`가 따로 있다(5자리 1,024개 중 593개가 6자리 자식을 가진다). 7·9자리도 같은 이유의 중간 수준이다.
3. 대신 **자식이 하나뿐이라 세분되지 않는 HS6는 06시트에 행이 없다**. 화이트리스트 24개 중 3개가 여기 해당한다 — `852692`(10자리 자식 1개 `8526920000` 「무선원격조절기기」)·`854142`(`8541420000`)·`901420`(`9014200000`).
4. 따라서 HS6 공식 명칭 = ① 06시트 6자리 행 → ② 없으면 10시트에서 앞 6자리가 같은 행이 **정확히 1개**일 때 그 이름(`hs6_name_src='10시트단일'`) → ③ 그래도 없으면 NULL. **자리수를 늘리거나 0을 채우지 않는다.** `v_hs6_candidate_rule`은 ①만 쓰므로 R2의 「HS6 명칭 용도어」 경로에서 이 3개는 명칭 근거를 쓸 수 없다. 다만 셋의 10시트 이름(`무선원격조절기기`·`광전지…`·`항공용이나 우주항행용 기기…`) 중 용도어 정규식(`레이더|항행|항공기용|항공용|우주항행|무인기`)에 걸리는 것은 901420뿐이고, 901420은 HS10 용도 태그로 이미 `r2_aero_nav=1`이다(2026-09-19 실측). **즉 ②를 뷰에 넣어도 R1~R4·`is_candidate_provisional`은 그대로**다 — 852692는 `전략물자-DU;B2-FSC`(R3∧R4), 854142는 근거 없음으로 변화 없음. 뷰를 ②까지 넓힐지는 팀 확인 뒤로 미룬다(**잠정**).
